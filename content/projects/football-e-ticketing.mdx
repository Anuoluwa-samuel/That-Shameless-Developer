## Overview

An e-ticketing system for a football organisation, designed around one unusual rule: tickets for a session can only be bought inside a short window shortly before it starts. Buyers pay with Paystack, receive a QR ticket, and are admitted by a gate scan.

This is a product and systems-design case study. My deliverables were the full product requirements document (PRD) and a 12-week phased delivery plan.

## Architecture

The flow runs from the session schedule to the gate:

1. Each session has a purchase window. The example in the PRD is a 20-minute window that opens one hour before the session.
2. A buyer pays through Paystack inside the window.
3. A QR ticket is generated for the purchase.
4. At the gate, the scan checks that the ticket is valid and unused, then marks it used.

## Key decisions & trade-offs

- **Time-gated purchase window.** The server decides whether the window is open, never the buyer's device clock. This keeps the rule enforceable. The trade-off is that a short window concentrates demand, so the system must handle a burst.
- **QR tickets validated against the server.** The gate checks the ticket's state rather than trusting the code alone, so a photographed or duplicated QR can be admitted only once. The trade-off is that the gate needs connectivity, or a defined offline fallback.
