## Overview

A live portfolio site for a photographer, with a private admin dashboard where the owner manages enquiries, gallery uploads and services without touching code. It is deployed and in use at yit0shotit.com.

## Problem

A photographer needs a site that shows photographs quickly and lets the owner update galleries and answer enquiries on their own. Photographs are heavy, and the owner is not a developer, so both performance and the admin experience matter.

## My role

I designed and built all of it: the public site, the admin dashboard, the Express API, the database schema, file uploads, deployment and the security hardening of the admin.

## Architecture

Public pages are rendered by Next.js on Vercel. An Express API, mounted inside the Vercel deployment, powers the admin dashboard. Data lives in Turso (libSQL, a SQLite-compatible database) and uploaded photographs live in Vercel Blob.

## Key decisions & trade-offs

- **Put the database next to the compute.** Moving Turso from Oregon to Ireland and pinning the functions to the nearby region cut page render, measured from Lagos, from 2.02 s to 0.97 s. The trade-off is one fixed region.
- **Photographs in object storage, not the database.** Blob stores the files and the database stores their URLs. Uploads are shrunk in the browser first so they stay under Vercel's 4.5 MB request limit.
- **Admin hardening.** Production refuses to start with a weak session secret, rate limits are stored in the database so they hold across serverless instances, and a password change signs out other devices.
- **Admin pages kept out of `public/`.** Anything in `public/` is served by the CDN before any function runs, which would bypass the login check.
- **One Express codebase for local and Vercel.** It keeps local development simple. The trade-off is that Next's file tracing cannot see packages loaded through the Express layer, so those dependencies are traced explicitly at build time.

## Results

The site is live and the owner manages content through the dashboard. The measured result is the page-render improvement above: 2.02 s down to 0.97 s from Lagos.

## What I'd do next

- Add automated tests around admin login and the rate limits.
- Redirect the retired Vercel URL to the custom domain.
- Add basic analytics so the owner can see which galleries get attention.

## Stack

Next.js, Node.js, Express, SQLite via libSQL on Turso, Vercel Blob, and Vercel.
